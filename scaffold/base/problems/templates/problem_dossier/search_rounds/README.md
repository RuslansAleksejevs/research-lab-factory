# Search Rounds

Store one report per substantive proof-search round, using
`templates/search_round_report.md` as the shape.

Each report must preserve:

- the round's distinct information objective;
- context exposure and independence lineage for every branch;
- concrete artifacts returned;
- semantic clustering by mathematical mechanism;
- attacks on load-bearing lemmas;
- route status transitions and reasons;
- target-bound historical-backfill manifests for imported first transitions,
  whose source set includes the transition evidence;
- reciprocal merge edges and one typed discharge per closed inherited gap;
- a strictly later redirected-wave round, parent manifest, triggering failures,
  entirely new duplicate-free mechanism delta, and discriminating question;
- or, for a waiver, a target-bound assessment of every canonical discovery
  operator exactly once with an allowed status and reason, with the unavailable
  list derived from `UNAVAILABLE`/`NOT_APPLICABLE` statuses;
- resource reallocation and the next checkpoint.

Do not create a new round merely to repeat a blocked route in new notation.
Structural validation checks only the declared current snapshot; it neither
proves the mathematics nor detects history deleted before validation.
